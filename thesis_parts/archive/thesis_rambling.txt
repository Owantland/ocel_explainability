Intro and Preliminaries
	Predictive process monitoring refers to the practice of predicting the outcome of an ongoing process before the process is finished in order to give stakeholders a chance to influence the process output.
	Predictive process monitoring relies on the concept of Object Centric Event Logs, a way to represent a business process flows through the relationship between events in a process execution and the different objects associated with each event step.
		An OCEL table would show all the object types (with their respective IDs) of the objects related to that particular event, for example the items associated with a particular order or the truck assigned to perform a delivery
		All this information is taken from the initial database, we need to have our events and objects clearly defined as well as the relationship between events to objects and objects to objects. The event-to-event relationship can be inferred from the provided information
		A core elements of OCELS are the process executions or traces. Traces can be defined in two ways, the one we chose refers to selecting a viewpoint object to serve as the basis for identifying the events and relationships that make up a whole process. In other words, we choose a start point for each trace, and given a certain connection depth or hop distance we can identify the end of the process. 
		Traces can be broken down into their individual event steps, also known as prefixes. A given prefix defines the trace at a particular moment in time.
		In a graph point of view each trace is a strongly connected component of the original graph.
		Explain how this means we end up with a list of distinct elements as opposed to one huge, interconnected graph. A global envisioning of the process is possible but is outside the scope of this thesis (Mention Pietro's work in the area)
		KPIs: A KPI is described as a function T that, given a trace and a value i provides the value of a given measure in the trace after i events have occurred. Two common examples can be
			- Time remaining: How much time is left until the current process ends at any given event in the trace. Calculated as end_ev_time - current_ev_time
			 - Appearance of an event: Calculates the probability of a certain event happening in the current trace. At any given point in the trace, before the trace appears the KPI can have value either True (if the event will happen) or False (If the event won't happen in the future.)
		Prediction problem: As stated before, the goal of a predictive process monitoring process is to provide a prediction for a certain KPI value given the current information in the trace. Formally it wants to find a prediction for T() at a given value i where i is higher than the value of i at the current time.
		In order to perform this prediction we can use different methods, chief among them Neural Networks given their predictive power.

		An important aspect to note is that OCEL data can be presented in a variety of forms. Traditional architectures presented the information as a series of steps in a table, however this assigns a temporal constraint on the information, making it seem like there is stringent process ordering when, in reality, different processes could be occurring at the same time. 
			Because of this graph respresentations are considered to be a lossy way of representing OCEL information and have been pushed out of use in favor of methods that preserve the original information of the process system.
			-- Check Adams for the intermediate point between table and graph -- 
			Graph representation: The OCEL can also be represented as a graph, with form (N, V) for nodes and vertices. These have become the standard way of defining OCEL's given their ability to encode the information present in the process definition without having to change its original form.
				Homogeneous: Homogeneous representations defined the OCEL as a series of event nodes that are connected in the graph when they events have the same object related to them. For example, the CreateOrder(?) event has an associated Order and item objects so it will be connected to other events (within a defined hop distance) that also use those objects (For example, the PickItem events and the ConfirmOrder event)
				Heterogeneous: Given the benefit of representing the OCEL in it's original graph form heterogeneous graphs allow for an even more complete representation, allowing the use of different node and edge types to properly represent the flow of the process. Here, it's not just event nodes connecting to other event nodes to denote the flow of the process, it's object nodes denoting the appearance of new elements (and their assigned attributes) as the process flows. Ideally, it should allow for more powerful predictive models by encoding even more information about the process into the already benefitial graph implementation.
